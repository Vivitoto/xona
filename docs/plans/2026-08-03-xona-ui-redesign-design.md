# Xona UI Redesign Design

## Goal

把 Xona 从“传统后台表单”改成现代、紧凑、规整的本地工具界面。全站统一视觉系统、按钮尺寸、Tab、卡片、列表、弹窗和页面信息架构，同时保留分页、滚动容器和弹窗这些已经确认的交互原则。

## Scope

覆盖全站前端 UI：

- 全局布局、侧边栏、页头、主题变量。
- Button、Tab、表单、卡片、状态 pill、表格、日志、弹窗。
- Dashboard、本地元数据、XChina 搜索、整理记录、演员库、日志、设置页。
- 清理冗长文案和不必要注释。

不包含：

- 后端业务逻辑改造。
- 新增发布、推送、Docker 镜像发布。
- 大规模改变 API contract。
- 把批量结果改成无限长展开页。

## Visual Direction

### Palette

采用浅色、低饱和、灰阶为主的工具界面：

- 背景：暖灰白，不使用蓝紫渐变。
- 卡片：白色或极浅灰。
- 文字：近黑灰，不用纯黑大面积压迫。
- 边框：浅灰与中性灰。
- Hover：浅灰底 + 灰边框。
- Selected：药丸形，白底或浅灰底 + 深灰描边。
- 状态色：只在 success / warning / danger 中小面积出现，全部低饱和。

主色不做大面积黑底白字。只有危险确认或极少数小面积 CTA 可以用较深底色，但默认主按钮优先使用描边、轻填充、清晰边框。

### Buttons

按钮重新分层，避免浪费页面空间：

| Type | Height | Use |
| --- | --- | --- |
| Compact | 30–32px | 表格行内操作、次级工具栏 |
| Default | 34–36px | 普通表单操作 |
| Primary | 36px | 每个主要区域唯一主操作 |
| Icon | 30–32px square | 刷新、关闭、展开、返回 |
| Danger | 34–36px | 删除、执行高风险动作 |

规则：

- 同一 button row 内按钮等高。
- 图标统一 15–16px，避免大图标撑高。
- 默认按钮圆角 999px 或 10–12px，优先 pill。
- 文案按钮不超过 6–8 个字；长动作放 tooltip/title 或上下文标题。
- 表格行内按钮必须 compact，不得使用大 CTA。
- 每个 section 最多一个 primary，其余为 secondary / ghost。
- Disabled 状态降低透明度但保持布局尺寸。

### Tabs

Tab 使用 segmented pill：

- 外层浅灰底、圆角 pill。
- Active tab：白底或浅灰底 + 深灰描边。
- Hover：灰底 + 边框增强。
- 不使用强色填充。
- 横向可滚动，避免挤压换行。

### Cards and Sections

- Section 更平，主要靠边框、留白、标题层级区分。
- 去掉厚重阴影和装饰渐变。
- 卡片圆角统一 16px 左右。
- 内容密度提高，但不牺牲可读性。
- 高频操作靠前；高级设置折叠或放次级卡片。

## Information Architecture

### Global Layout

- 侧边栏继续作为一级导航，但改成紧凑 pill 菜单。
- 页头保留版本、安全模式、主题切换，但减少视觉重量。
- 内容区最大宽度更可控，避免超宽屏上表单拉得太散。
- 页面使用一致的 `page-stack`、`section-grid`、`toolbar`、`table-wrap`。

### Dashboard

目标：入口清楚，不堆说明。

结构：

1. 顶部紧凑 hero：一句定位 + 主要入口。
2. 入口矩阵：未处理文件、元数据复核、任务与记录、历史线索。
3. 小指标：演员库、任务状态等真实数据；没有 API 支撑的不展示。
4. 流程 strip：扫描 → 草稿 → 封面/NFO → 预览 → 记录。

### Local Metadata

目标：输入输出分区，批量不摊满页面。

单个流程：

1. 源文件与截图。
2. 封面与素材。
3. 元数据 / NFO。
4. 整理预览 / 执行。

批量流程：

1. 扫描条件。
2. 批量规则。
3. 任务提交。
4. 结果列表。

规则：

- 批量结果使用限制高度、分页或 “显示前 N 条”。
- 单项详情默认折叠。
- 预览图网格紧凑，不让图片无限撑高页面。
- 日志使用滚动区。

### XChina Search

目标：搜索、结果、详情分区明确。

- 搜索条件在顶部或左栏。
- 结果列表紧凑显示。
- 详情预览单独卡片。
- 候选图遵守安全模式。

### Tasks / Review / History

目标：像任务控制台，不像裸表格。

- 顶部状态 pill / metric。
- 列表区紧凑。
- 详情、计划、日志使用固定高度滚动区。
- 操作按钮按风险分层。

### Actor Library

目标：筛选、列表、详情整齐。

- 筛选区紧凑。
- 演员卡片或表格统一密度。
- 合并弹窗遵守新按钮和卡片样式。

### Logs

目标：本地排障面板。

- 外层浅色工具面板。
- 日志正文仍使用暗色 console 以保证可读。
- 筛选、刷新、清屏按钮 compact。
- 日志区限高滚动。

### Settings

目标：少堆叠，少解释。

- 顶部 pill tabs。
- 每个设置组用紧凑 grid。
- 高频字段靠前。
- 低频说明收进 help 文案或 details。
- 删除 AI 味长注释、重复说明。

## Copy and Comments

UI 文案：

- 多用短动作词：扫描、生成、预览、执行、刷新、重试、查看。
- 少用“智能”“自动化”“工作台能力”这类空词。
- 描述控制在一行优先。
- 错误提示保留原因和可操作下一步。

代码注释：

- 删除重复解释和 AI 味注释。
- 只保留非显然边界、风险原因、兼容性说明。

## Interaction Constraints

必须保留：

- 分页或限制显示数量。
- 长列表滚动容器。
- 目录选择、详情确认、合并确认等弹窗。
- 图片安全模式。
- 表格横向溢出保护。

避免：

- 黑底白字作为默认设计语言。
- 大色块 CTA 横跨整行。
- 多个同权重主按钮堆在一起。
- 一屏塞满多个无层级表单。
- 把 100+ 批量结果全部展开。

## Testing Strategy

- 更新组件和页面测试中的可见文案断言。
- 保持现有业务交互测试通过。
- 前端至少运行：
  - `npm run lint`
  - `npm run build`
  - 相关页面 Vitest
- 样式改动后做一次本地页面检查或截图检查。

## Rollout Plan

分阶段实现，降低全站同时失控风险：

1. 全局设计变量和基础组件。
2. AppLayout、Dashboard、通用卡片/表单/Tab。
3. 本地元数据页。
4. XChina、任务、历史、日志、演员库。
5. 设置页。
6. 文案和注释清理。
7. 全量前端验证。
