# Xona v1.2 Product Restructure Design

## Background

Vito clarified that Xona should no longer be centered around automatic XChina-driven organizing. The current product model mixes several old concepts:

- Manual organizing tied to local-video scanning and XChina search
- Automatic monitoring/watch rules
- Confidence scoring and review queues
- A newly added "未匹配视频" page that actually implements local metadata generation

This makes the product confusing. The next version should simplify the product around two core features:

1. XChina metadata search
2. Local metadata generation, including single-item processing and batch tasks

Automatic monitoring is not needed. Confidence-based matching/gating is not needed.

## Product Principles

- XChina is a metadata source, not the organizing workflow.
- Local metadata generation is the main organizing workflow.
- Users explicitly choose files, edit/import metadata, preview output, then execute.
- System organization settings remain as defaults only.
- Path inputs must support both manual text input and a directory/path picker where applicable.
- UI should feel flatter, cleaner, more premium, and more technical.

## Target Navigation

Primary navigation should be reduced to the product's actual core capabilities:

```text
Dashboard / Overview        optional lightweight landing page
本地元数据生成              core feature
XChina 元数据搜索           core feature
任务记录                    local generation task/execution history
演员库                      keep if still useful for metadata/image reuse
历史/回滚                   keep if operation rollback remains exposed
设置                        defaults and connector settings
日志                        diagnostics
```

Remove from visible navigation:

```text
手动整理
未匹配视频
自动监控
复核队列
```

Mapping:

- `未匹配视频` -> rename/rebuild as `本地元数据生成`
- `手动整理` -> remove as a primary feature; reuse only the XChina search/details code behind `XChina 元数据搜索`
- `自动监控` -> remove from product UI
- `复核队列` -> remove as confidence-driven workflow; keep generic task errors in task/history pages if useful

## Core Feature 1: XChina 元数据搜索

### Purpose

Independent metadata lookup. It should not require selecting or scanning a local video first.

### User Flow

1. User opens `XChina 元数据搜索`.
2. User enters one of:
   - keyword/title/number
   - direct XChina detail URL
3. Xona searches/fetches XChina.
4. UI shows result cards and a details panel.
5. User can:
   - copy metadata
   - export/import the selected metadata into `本地元数据生成`
   - optionally download/cache source images for later use

### Not In Scope

- No local source directory scan.
- No automatic matching.
- No confidence threshold.
- No automatic organizing.
- No requirement to choose a local video.

### Backend Direction

Create a new explicit XChina API surface, likely:

```text
POST /api/xchina/search
POST /api/xchina/detail
GET  /api/xchina/image-proxy
```

Reuse existing adapter logic from `backend/app/api/manual.py` and `backend/app/services/manual.py`, but decouple it from jobs/media items.

Candidate scores may be kept internally for ranking if already produced by the adapter, but should not be exposed as a product gate called confidence.

## Core Feature 2: 本地元数据生成

### Purpose

Generate local metadata/artwork for local videos and optionally organize files into a target directory.

### Structure

`本地元数据生成` should contain two internal modes/tabs:

```text
单个处理
批量任务
```

### 单个处理 Flow

1. Select or type a local video path.
   - manual input
   - path/file picker
2. Analyze video.
3. Edit metadata draft.
4. Optionally import metadata from XChina search result.
5. Generate/select frames.
6. Generate poster/fanart/backdrops.
7. Preview NFO.
8. Configure output using defaults:
   - destination root
   - organization mode
   - folder templates
   - filename / organize filename
   - backdrop count
9. Preview operation plan.
10. Execute copy/move/hardlink/symlink after explicit confirmation.

### 批量任务 Flow

1. Select or type source directory.
   - manual input
   - directory picker
2. Select or type destination root.
   - manual input
   - directory picker
3. Apply defaults from system settings:
   - folder templates
   - filename template
   - organization mode
   - default tags/genres if supported
   - poster template/font defaults if supported
4. Scan videos.
5. Show a batch table:
   - source path
   - title
   - organize filename
   - output folder/path preview
   - metadata status
   - artwork status
   - conflict/error status\n6. Allow row editing or opening a row in the single-item editor.
7. Generate batch previews.
8. Execute batch task.
9. Show per-item status:
   - pending
   - drafted
   - previewed
   - conflict
   - completed
   - failed
   - skipped

### Batch Drafts

The current `批量草稿` concept should be replaced by real batch tasks. A draft is just one row/item state inside the batch task, not a top-level user-facing concept.

### Backend Direction

Existing `/api/local-metadata/*` is close to the new core and should be retained/refactored.

Current single-item APIs can remain:

```text
POST /api/local-metadata/analyze
POST /api/local-metadata/frames
POST /api/local-metadata/cover-preview
POST /api/local-metadata/nfo-preview
POST /api/local-metadata/preview-plan
POST /api/local-metadata/plans/{plan_id}/execute
POST /api/local-metadata/scan
```

Add/reshape batch APIs only if needed:

```text
POST /api/local-metadata/batch/scan
POST /api/local-metadata/batch/preview
POST /api/local-metadata/batch/execute
```

For first restructure, batch may be implemented mostly in frontend using existing per-item APIs if acceptable, but durable backend batch task state is preferred if execution status/retry matters.

## Settings Model

Settings remain, but should be repositioned as defaults:

```text
设置
├── XChina 连接
├── 本地元数据默认值 / 整理默认值
├── 元数据/资源默认值
├── Emby optional integration
├── 媒体目录 / 存储根
├── 认证
```

Remove/hide:

```text
置信度/安全
自动监控规则
confidence threshold
watch rule settings
```

Keep safety checks as hard operational validation, not product confidence concepts:

- storage root validation
- path traversal prevention
- collision detection
- generated artifact overwrite rules
- user approval before execution

## Backend Removal / Demotion

### Remove from UI and active product flow

- `AutomaticMonitorsPage`
- `WatchRuleEditor`
- `ReviewQueuePage`
- confidence settings page
- confidence labels in user-facing status

### Backend Compatibility

Immediate hard deletion of DB models/migrations is risky. Prefer staged removal:

1. Remove visible UI/routes from navigation.
2. Stop calling watch-rule and review APIs from frontend.
3. Keep backend endpoints temporarily for backward compatibility/tests.
4. Later remove watch worker/services/db tables in a dedicated cleanup migration only if safe.

This avoids breaking existing installed databases while still giving users the simplified product.

## UI/Visual Direction

Current UI feels too plain. v1.2 should introduce a flatter, more premium technical style.

### Theme

Support both light mode and dark mode. The top-right page header should expose a compact theme toggle next to the version badge / safety mode controls. Theme preference should persist locally and apply immediately without reload.

Recommended direction:

- dark mode: deep graphite/navy background, elevated dark cards, cyan/sky-blue accents
- light mode: clean off-white/slate background, white cards, same cyan/blue primary accent, slightly stronger borders for readability
- secondary accent: violet
- semantic states: green/yellow/red with restrained saturation

Candidate dark tokens:

```css
--bg: #0b1020;
--surface: #111827;
--surface-soft: #162033;
--border: rgba(148, 163, 184, 0.18);
--text: #e5eefb;
--muted: #94a3b8;
--primary: #22d3ee;
--primary-strong: #38bdf8;
--secondary: #8b5cf6;
--success: #10b981;
--warning: #f59e0b;
--danger: #ef4444;
```

Candidate light tokens:

```css
--bg: #f6f8fb;
--surface: #ffffff;
--surface-soft: #eef4fb;
--border: rgba(15, 23, 42, 0.12);
--text: #0f172a;
--muted: #64748b;
--primary: #0284c7;
--primary-strong: #0ea5e9;
--secondary: #7c3aed;

Implementation notes:

- Add a `ThemeModeProvider` or equivalent app-level state.
- Store preference in `localStorage`, with system preference as the initial fallback.
- Apply `data-theme="light|dark"` on the app shell or document root.
- Keep image safety mode independent from color theme.
```

### Micro-interactions

Use subtle effects only:

- active nav glow line
- card hover lift
- button hover highlight
- skeleton shimmer for preview generation
- path picker modal fade/scale
- toast/status chips for success/failure
- smooth tab transitions

Avoid heavy cyberpunk/glassmorphism that hurts readability.

`PathPickerField` should compose:

- optional directory picker button

## Data Flow

### XChina Search

```text
query/url -> /api/xchina/search or /api/xchina/detail -> results/details -> optional import metadata into local generation draft
```

### Local Single

```text
video path -> analyze -> draft -> frames -> artwork preview -> nfo preview -> plan preview -> execute
```

### Local Batch

```text
source dir -> scan -> batch rows -> apply defaults -> per-row edit/import -> batch preview -> batch execute -> per-row result
```

## Testing Strategy

Frontend:

- navigation shows only new core product structure
- `本地元数据生成` has `单个处理` and `批量任务`
- path fields expose text input + picker controls
- XChina search works without local video/job id
- no visible `自动监控`, `置信度`, `未匹配视频`, or old `手动整理` primary nav labels
- local metadata settings default into single/batch forms

Backend:

- xchina search endpoint works without job/media item
- xchina detail endpoint works with direct URL
- local metadata existing tests remain green
- settings validation no longer requires confidence as user-facing config
- old backend endpoints may remain compatible during staged cleanup

Release gate:

- Run full `scripts/release_gate.sh` before release.
- When using proxy, include `NO_PROXY=127.0.0.1,localhost,::1`.
- For local source Docker builds in China, pass `APT_MIRROR` / `APT_SECURITY_MIRROR`.

## Recommended Implementation Phases

### Phase 1 — Product IA and labels

- Replace nav with new structure.
- Rename `未匹配视频` to `本地元数据生成`.
- Remove `自动监控`, `复核队列`, and old `手动整理` from nav.
- Keep backend compatibility.
- Update dashboard cards and tests.

### Phase 2 — XChina metadata search page

- Extract XChina search/detail UI from manual organizer.
- Add backend `/api/xchina/*` endpoints independent of local jobs.
- Remove confidence display/gates from search UI.
- Add import-to-local-metadata handoff if practical.

### Phase 3 — Local metadata generation page restructure

- Split into `单个处理` and `批量任务` tabs.
- Replace `批量草稿` with batch task table language.
- Add consistent path input + picker patterns.
- Ensure system organization settings populate defaults.

### Phase 4 — Remove confidence/monitor UI and polish theme

- Remove confidence settings tab.
- Remove monitor UI components from active app.
- Update progress/status labels away from confidence/review-required concepts.
- Apply new theme tokens, card styling, micro-interactions.

### Phase 5 — Deep cleanup

- Decide whether to delete or keep dormant backend watch-rule/manual-organizer internals.
- If deleting DB-backed watch models, do a careful migration plan.

## Open Questions

1. Should actor library remain in primary navigation for v1.2, or be moved under settings/tools?
2. Should Emby remain visible as a first-class setting now, or become optional advanced integration?
3. Should batch execution be durable backend jobs in v1.2, or is frontend-orchestrated batch acceptable for the next patch?

## Recommendation

Implement v1.2 in stages, starting with navigation/product-model correction and independent XChina search. Avoid immediate destructive backend/database deletion. The user-facing product should become simple now; backend cleanup can be staged safely.
